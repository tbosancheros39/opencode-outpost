## Section A: Orchestrator Setup & Protocols

### A1. Orchestrator's Role & Constraints

| Rule | Mandate |
|------|---------|
| **No self-execution** | Orchestrator never implements code. All work delegated to `@general` subagents |
| **Sequential only** | One subagent at a time. Each completes before next starts. Never parallel. |
| **Zero fabrication** | No invented facts, code, or capabilities. Low-confidence items flagged for re-verification |
| **Tool-call reliability** | Every subagent response must be valid JSON matching given schema. Malformed responses re-issued with: *"Reply with single valid JSON object matching schema. No explanatory text."* |
| **Hallucination-aware** | Every output audited by a FactCheck subagent before acceptance |
| **Confidence tagging** | Every reasoning step tagged `[HIGH]` or `[LOW]` with source |
| **Long-context management** | Critical constraints at start AND end of every delegation prompt |

### A2. MCP Tool Inventory & Activation Sequence

**Before any layer begins, the orchestrator MUST run:**

```bash
# [1] Serena project activation
serena_activate_project(project_name="opencode-outpost")

# [2] Read Serena's accumulated project knowledge
serena_read_memories()

# [3] Fetch specific symbols (key functions, classes, types)
serena_fetch_symbol(symbol_name="<name>")
# Returns: exact file path, line numbers, signature

# [4] Find usage patterns across codebase
serena_fetch_pattern(pattern="<regex>")
# Returns: all occurrences with file paths + line numbers
```

**Additional MCP tools available per layer:**

| Tool | Purpose |
|------|---------|
| `context7_query-docs` | Check SDK/grammy/bullmq changelogs for breaking changes |
| `firecrawl_scrape` | npm registry, GitHub CI status, community discussions |
| `bash` (npm view, git) | Dependency diffs, git log, build verification |
| `grep` / `glob` | Codebase search for version references, patterns |
| `read` / `edit` / `write` | File inspection and modification (by subagents) |

### A3. Subagent Delegation Protocol

**Every `@general` subagent instruction MUST follow this template:**

```
load caveman skill

Task: [one-sentence goal]
Files: [exact absolute paths to read or modify]
Context: [what previous tasks established]
Verify: [how to self-check correctness]

IMPORTANT: Reply with single valid JSON object. No explanatory text outside JSON.

Schema:
{
  "status": "success|failure",
  "summary": "one-line result",
  "artifacts": ["path:line — what changed"],
  "verification": {
    "selfCheck": "proof of correctness",
    "evidence": "command output or file excerpt"
  },
  "confidence": "high|medium|low",
  "notes": "warnings or suggestions"
}
```

### A4. FactCheck Verification Protocol

**After every `@general` subagent returns JSON, spawn a FactCheck subagent:**

```
load caveman skill

FactCheck audit: verify [previous subagent's claims]
- Re-run verification command independently
- Cross-reference artifacts list against actual file state
- Report: VERIFIED | NEEDS_REWORK | UNRELIABLE

Schema:
{
  "verdict": "VERIFIED|NEEDS_REWORK|UNRELIABLE",
  "discrepancies": ["list of mismatches between claim and reality"],
  "reRunEvidence": "command output from independent re-run",
  "confidence": "high|medium|low"
}
```

**Escalation rules:**
- `NEEDS_REWORK` → Re-issue original task with tightened constraints
- `UNRELIABLE` → Escalate to human review. Do not proceed.

### A5. Confidence Tagging Standard

| Tag | Meaning | Example |
|-----|---------|---------|
| `[HIGH — source: Serena symbol fetch]` | Symbol location confirmed by MCP | `src/bot/commands/start.ts:42` |
| `[HIGH — source: context7 docs]` | API behavior confirmed by docs | grammy v1.43 CHANGELOG |
| `[HIGH — source: npm registry]` | Version confirmed by `npm view` | package version 1.16.2 |
| `[HIGH — source: git log]` | Commit history confirmed | `git log --oneline` |
| `[MEDIUM — source: code inference]` | Inferred from code reading but not explicitly documented | "handler probably returns string" |
| `[LOW — needs verification]` | Assumption or best guess | "this error path likely untested" |
